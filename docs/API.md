# HTTP API

Versioned REST API under `/api/v1`, served by the Spring Boot backend and consumed by the React
SPA (Vite dev proxy in development, Nginx in containers). The machine-readable contract is
generated by springdoc:

- OpenAPI JSON: `GET /api/v1/openapi.json`
- Swagger UI: `GET /api/v1/swagger.html`

Both are development/documentation endpoints; the Nginx edge exposes only `/api/**` and the
internal actuator (see `docs/DEPLOYMENT.md`).

## Conventions

- **Content type:** JSON request/response bodies (`application/json`).
- **Authentication:** server-side session cookie (`SESSION`, `HttpOnly`, `SameSite=Lax`,
  `Secure` in production) established by `POST /api/v1/auth/login`.
- **CSRF:** double-submit — the readable `XSRF-TOKEN` cookie must be echoed in the
  `X-XSRF-TOKEN` header on every POST/PUT/PATCH/DELETE.
- **Authorization:** enforced server-side on every endpoint (`ROLE_STUDENT` / `ROLE_ADMIN`);
  object ownership (course, enrollment, attempt, progress) is re-checked in the service layer.
  Frontend route guards are usability only.
- **Errors:** a single problem shape —
  `{"timestamp","status","error","message","path","fieldErrors"}` — with honest `401` (not
  signed in), `403` (forbidden / suspended account, with reason), `404` (not visible to you),
  `409` (illegal state transition), `422` (validation). Stack traces and messages are never
  leaked (`server.error.include-message/stacktrace: never`).
- **Publication visibility:** draft content is invisible to students everywhere; reads return
  404 rather than leaking existence.

## Endpoints

### Public (anonymous)

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/v1/health` | Liveness payload used by health checks and the SPA |
| GET | `/api/v1/public/overview` | Catalog counts (paths, courses, start-here) |
| GET | `/api/v1/public/paths` | Published learning paths |
| GET | `/api/v1/public/paths/{slug}` | Path detail with its published courses |
| GET | `/api/v1/public/courses` | Published courses (filterable) |
| GET | `/api/v1/public/courses/{slug}` | Course detail, prerequisites, approved-enrollment count |
| GET | `/robots.txt` | Crawler policy: allow public pages, disallow `/student`, `/admin`, `/api/`, `/actuator/`; advertises the sitemap |
| GET | `/sitemap.xml` | Absolute-URL sitemap: the static public routes plus every published path/course, using the same visibility rules as the public API (`lastmod` from `updated_at`) |
| POST | `/api/v1/contact` | Submit the public contact form; validates name/email/subject/message, stores it for administrator review, returns an ack-only 201 (no data echoed, no mail is sent) |

The two crawler files are generated by `SeoController` at the site root, outside
the `/api/v1` prefix. The Vite dev proxy and the Nginx edge both forward these
two paths to the backend, so development and the container stack expose
identical crawler behavior. Absolute URLs use `APP_PUBLIC_BASE_URL` when
configured (required in production); otherwise the origin is derived from the
request (`Host` + `X-Forwarded-Proto`, validated — a spoofed `Host` can never
inject markup into the sitemap).

`POST /api/v1/contact` is intentionally the only anonymous write: it keeps the
CSRF token (session-less double-submit cookie), rate of abuse is bounded by
validation limits (subject/message length), and the response never echoes the
stored data. Contact messages are read only through the admin inbox below.

### Identity

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/v1/registration` | Submit a student registration (creates `PENDING`) |
| POST | `/api/v1/auth/login` | Sign in; refuses non-`ACTIVE` accounts with an honest reason |
| GET | `/api/v1/auth/me` | Current session user, or 401 |
| POST | `/api/v1/auth/change-password` | Self-service password change (authenticated; re-proves the current password with a field-scoped 400, enforces the 8–72 policy, never echoes either password, keeps the session signed in) |
| POST | `/api/v1/auth/logout` | End the session (configured in `SecurityConfig`) |

### Student (`ROLE_STUDENT`, ownership-scoped)

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/v1/me/learning` | Dashboard (enrolled courses, progress, continue target) |
| GET | `/api/v1/me/learning/courses/{courseSlug}` | Enrolled-course outline |
| GET | `/api/v1/me/learning/courses/{courseSlug}/lessons/{lessonId}` | Sanitized lesson content |
| POST | `…/lessons/{lessonId}/access` | Record access (approved enrollment + PUBLISHED only) |
| POST | `…/lessons/{lessonId}/complete` | Mark complete; advances continue target |
| GET | `/api/v1/me/enrollments` | Own request history |
| GET | `/api/v1/me/enrollments/{courseId}` | Own enrollment for one course |
| POST | `/api/v1/me/enrollments/{courseId}` | Request access to a published course |
| GET | `/api/v1/me/assessments` | Published assessments with attempt history |
| POST | `/api/v1/me/assessments/{assessmentId}/attempts` | Start/resume an attempt (idempotent) |
| POST | `/api/v1/me/assessments/attempts/{attemptId}/submit` | Submit inside the server-derived window |
| GET | `/api/v1/me/assessments/attempts/{attemptId}` | Stored result with own answers |
| GET | `/api/v1/me/announcements` | Published announcements (platform-wide or approved course) |

### Administrator (`ROLE_ADMIN`)

| Area | Method | Path |
|---|---|---|
| Dashboard | GET | `/api/v1/admin/dashboard` |
| Students | GET, POST | `/api/v1/admin/students`, `…/{id}/suspend`, `…/{id}/reactivate` |
| Registrations | GET, POST | `/api/v1/admin/registrations`, `…/{id}/approve`, `…/{id}/reject` |
| Enrollments | GET, POST | `/api/v1/admin/enrollments`, `…/{id}/approve`, `…/{id}/reject` |
| Paths | GET, POST, PUT, POST | `/api/v1/admin/paths`, `…/{id}`, `…/{id}/status` |
| Courses | GET, POST, PUT, POST | `/api/v1/admin/courses`, `…/{id}`, `…/{id}/status` |
| Modules | GET, POST, PUT, POST | `/api/v1/admin/courses/{id}/modules`, `/api/v1/admin/modules/{id}`(+`/status`) |
| Lessons | GET, POST, PUT, POST | `/api/v1/admin/modules/{id}/lessons`, `/api/v1/admin/lessons/{id}`(+`/status`) |
| Assessments | GET, POST, PUT, DELETE, POST | `/api/v1/admin/courses/{courseId}/assessments`, `/api/v1/admin/assessments/{id}`(+`/status`) |
| Content import | GET, POST, POST | `/api/v1/admin/content/*` (source, run, conflict accept/discard) |
| Announcements | GET, POST, PUT, POST | `/api/v1/admin/announcements`, `…/{id}`, `…/{id}/status` |
| Messages | GET, POST | `/api/v1/admin/contact-messages` (inbox, unread first), `…/{id}/read` (idempotent) |
| Audit log | GET | `/api/v1/admin/audit` (entityType/limit filters) |

Publication state never comes from a write payload: status changes go through the explicit
`…/status` transition endpoints (see `docs/ARCHITECTURE.md`).

### Actuator (internal)

`GET /actuator/health`, `GET /actuator/info` only; `env`, `beans`, `metrics` are not exposed
(covered by `SecurityHardeningTest`). Nginx additionally restricts `/actuator/` to private
networks.

## Data contracts

DTO records live next to their controllers (`…/api/**`). Request validation uses Bean
Validation (`@Valid`); response shapes are asserted by contract tests
(`AssessmentJsonContractTest`, API suites). Never serialize JPA entities directly.

## Versioning

Breaking changes require a new prefix (`/api/v2`) — `/api/v1` stays backward compatible within
a release line. Additive fields are allowed; clients must ignore unknown fields.
